This guide explains how to set up HERITRACE for local development from source code.

## Prerequisites

- Docker and Docker Compose
- Git
- GNU Make
- 7-Zip
- About 175 GB of free disk space for the first download of the OpenCitations Meta database
- Modern web browser

## Development environment setup

### 1. Clone the repository

```bash
git clone https://github.com/opencitations/heritrace.git && \
cd heritrace
```

### 2. Configure environment

Copy the example environment file and edit it with your settings:

```bash
cp .env.example .env
```

The default configuration runs in demo mode (`FLASK_ENV=demo`), which bypasses ORCID authentication. To enable ORCID login, set `FLASK_ENV=development` and configure `ORCID_CLIENT_ID`, `ORCID_CLIENT_SECRET`, and `ORCID_SAFELIST` in `.env`.

### 3. Start development environment

```bash
make dev
```

Development runs on the full [OpenCitations Meta](https://doi.org/10.5281/zenodo.23063958) database, so that performance problems show up at production scale. On the first run, `make dev` downloads the QLever index from Zenodo into `dev/data/meta`. The download is 56.6 GB, and the extracted index takes about 116 GB. Later runs reuse the local copy.

Then `make dev` starts:
- QLever with the Meta data on `localhost:7101`
- QLever with the provenance on `localhost:7103`, starting from an empty index
- the application on `https://localhost:5000`, with an internal Redis

## Development features

### Demo mode
`make demo` starts the same environment as `make dev` with `FLASK_ENV=demo`, which bypasses ORCID authentication. You can also set `FLASK_ENV=demo` in `.env` to use demo mode with `make dev`.

### Hot reload
Gunicorn runs with `--reload`, so changes to Python files automatically restart the workers. Watched paths include:
- Python source files in `heritrace/`
- `app.py`, `config.py`

### Volume mounts
The following directories are mounted for live editing:
- `./heritrace` → Application source code
- `./default_components` → Optional URI generator, counter handler, and save plugin implementations
- SHACL schema and display rules from `example_configurations/`
