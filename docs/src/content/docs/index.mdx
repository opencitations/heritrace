HERITRACE is a web-based semantic data editor. It lets users enrich and edit RDF metadata through a web interface, without requiring knowledge of the Semantic Web. It handles provenance and change tracking, validates data against SHACL schemas, and connects to existing triplestores with no data transformation needed.

## Prerequisites

- <a href="https://docs.docker.com/get-docker/" target="_blank" rel="noopener noreferrer">Docker and Docker Compose installed</a>
- Modern web browser

## Setup

This method uses official Docker images published to Docker Hub and GitHub Container Registry. All configuration is done through environment variables in the docker-compose.yml file.

### 1. Download the compose file

Create a new directory for HERITRACE and download the configuration:
```bash
mkdir heritrace && cd heritrace
curl -o docker-compose.yml https://raw.githubusercontent.com/opencitations/heritrace/main/docker-compose.yml
```

### 2. Launch

```bash
docker compose up
```

The compose file includes two Virtuoso databases and the web application. Once the databases pass their health checks, the application starts automatically.

HERITRACE runs in demo mode by default (`FLASK_ENV=demo`) for immediate testing without authentication setup.

To use your own databases instead, edit `docker-compose.yml`: remove the `dataset-db`, `provenance-db`, and `networks` blocks, remove `depends_on` and `networks` from the `web` service, then set `DATASET_DB_URL` and `PROVENANCE_DB_URL` to your database endpoints.

## Access the application

Open your browser and navigate to:

```
http://127.0.0.1:5000
```

:::note[Demo vs Production Mode]
**Demo Mode**: Runs on HTTP with authentication bypassed for immediate testing. **Production Mode**: Requires HTTPS, valid SSL certificates, and ORCID authentication setup - see [Application Settings](/heritrace/configuration/app-settings/) for configuration details.
:::

## Pre-configured data model

HERITRACE comes preloaded with validation and display rules based on a customized version of the <a href="https://doi.org/10.1007/978-3-030-62466-8_28" target="_blank" rel="noopener noreferrer">OpenCitations Data Model (OCDM)</a>:

- **SHACL schema** (`./shacl.ttl`): Defines the data model, classes, and properties.
- **YAML display rules** (`./display_rules.yaml`): Configure how entities appear in the interface
- **Default components** (`default_components/`): Contains the default URI generator and counter handler implementations

## What's next?

Now that HERITRACE is running, you can:

1. **Explore the interface**: Navigate through the metadata management features with the preconfigured data model
2. **Production setup**: Configure [ORCID authentication and security settings](/heritrace/configuration/app-settings/) for production use
3. **Configure schemas**: Customize the [SHACL schema](/heritrace/configuration/shacl/) for your data model
4. **Set display rules**: Modify the [YAML display rules](/heritrace/configuration/display-rules/) for your interface

## Stopping the application

Press Ctrl+C in the terminal running docker compose, or run:
```bash
docker compose down
```

## Troubleshooting

### Port already in use
If you get a port conflict on 5000, check what is using it:

<Tabs>
  <TabItem label="Linux">
    ```bash
    ss -tulpn | grep ':5000\s'
    ```
  </TabItem>
  <TabItem label="macOS">
    ```bash
    netstat -an | grep ':5000\s'
    ```
  </TabItem>
  <TabItem label="Windows">
    ```powershell
    Get-NetTCPConnection | Where-Object {$_.LocalPort -eq 5000}
    ```
  </TabItem>
</Tabs>
